# Founders Plot Three.js Playable Slice

Status: implementation note
Branch: `codex/founders-plot-threejs-playable-slice`
Date: 2026-05-24

## Product Intent

Founders Plot should read first as a browser-playable game. The player enters the town, clicks objects in the scene, makes progress through clear game actions, and sees Clover as an in-world helper. Agent Town platform and worker details stay behind the game surface.

## Three.js-First Architecture

The Three.js slice is a renderer change, not a game-logic rewrite.

- Server-authoritative simulation stays in `server/founders_plot/*`.
- The `et.plot.*` tool contract remains the only gameplay mutation path.
- `public/experiences/founders-plot/scene_state.js` remains the scene adapter from state to world objects.
- `public/experiences/founders-plot/three_scene_entry.js` renders those scene objects with Three.js in an orthographic 2.5D scene.
- `public/experiences/founders-plot/scene_render.js` keeps stable semantic DOM hooks for accessibility, object identity, and older Playwright contracts while syncing the Three.js canvas.
- `public/experiences/founders-plot/three_scene_bundle.js` is generated by `npm run build:founders-plot-threejs`.

## 1:1 Replacement Boundary

The first 1:1 replacement applies to the **world/game surface** that previously lived in layered DOM: stage background, build pads, buildings, special objects, Clover, state labels, badges, production timers, target links, selected/goal/action highlights, and normal pointer interaction.

Full gameplay-state parity is tracked in `specs/45_founders_plot_threejs_full_state_coverage.md`. That contract expands the Three.js scene with canvas HUD rows, in-world state anchors, and selected-object detail so non-world domains such as contracts, rewards, approvals, policy, scheduler, standing order, journal, recap, and unlocks are visible in the canvas without moving game logic into the renderer.

The surrounding shell remains DOM by design:

- HUD/inventory strip
- quest ribbon and CTA
- action sheet
- drawer tray and drawers
- Brain/Foreman setup controls

Those surfaces are not part of the replaced world layer. They remain ordinary UI around the game scene until a later full-canvas HUD decision is made.

## Interaction Contract

Three.js raycasting maps in-scene picks back to the same world object IDs used by the DOM and game state. Canvas clicks dispatch `founders:three-pick`; `app.js` consumes that event and updates the existing selected object or drawer state. It no longer synthesizes clicks on visible DOM scene buttons.

The accessible DOM hooks remain as hidden semantic/test hooks for keyboard focus, labels, and older tests:

- lots: `PAD:x,y`
- buildings: building type/object ID such as `HQ` or `LUMBER_CAMP`
- Clover: `CLOVER`

The Three.js renderer records the last raycast pick in `window.__foundersPlotTest.getThreeSceneInfo()`. Existing action buttons still call `et.plot.*`, so tests and player actions continue to prove the real server-backed loop.

## Grid Contract

`scene_state.js` emits `grid.version = founders-plot-grid-v1` with an 8 by 5 grid over a 16 by 9 world. Each cell has:

- `id`: `GRID:col,row`
- normalized center `x` / `y`
- `primaryObjectId`, `selectionKey`, and `drawerKey` when a world object occupies or owns the cell
- placement flags: `buildable`, `locked`, `occupied`, `validPlacement`, `selected`
- pad coordinates when the cell maps to a server build pad

`three_scene_entry.js` draws the grid underneath the world objects, gives buildable cells a valid placement preview, gives locked cells muted invalid feedback, and exposes each cell in `getThreeSceneInfo().gridCellIds` and `pickTargets`.

## Visual Parity Contract

The scene adapter emits presentation state once; Three.js consumes it directly:

- `labelVisible`, `labelRole`, `selected`, `goalTarget`, and `cloverTarget` drive canvas labels and rings.
- Decorated `badges` drive canvas badge chips.
- `timer` drives canvas production progress rings.
- `scene.clover.bubbleText` drives the in-world Clover bubble.
- `scene.clover.targetObjectId` drives the in-world Clover target link.

`getThreeSceneInfo().parity` exposes rendered canvas-owned parity records for Playwright:

- `labels`
- `badges`
- `timers`
- `highlights`
- `cloverBubbles`
- `targetLinks`

The DOM scene layer stays mounted only as semantic/accessibility/test hooks. In normal unfocused play it must not visually contribute sprites, labels, badges, timers, or Clover bubbles.

## Future Asset Contract

The current world uses 2D sprite planes so GPT Image / imported 2D assets can become billboards in the scene without changing game logic. Future GLB assets can replace a sprite for an object if they preserve:

- the scene-state object ID;
- the grid cell or normalized world coordinate;
- the `selectionKey` / `drawerKey` mapping;
- the `et.plot.*` mutation path for any gameplay outcome.

## Acceptance Coverage

The baseline Playwright slice is `e2e/214_founders_plot_threejs_playable_slice.spec.js`.

It proves:

- `/app?district=founders-plot` opens Founders Plot in the existing modal.
- the Three.js canvas is visible and has nonblank WebGL pixels.
- the renderer exposes object identity and grid identity for `HQ`, `CLOVER`, build pads, and `GRID:col,row`.
- DOM scene sprites, labels, badges, timers, and Clover bubbles are hidden as semantic hooks instead of competing with the canvas.
- Three.js exposes parity records for labels, build badges, production timers, ready badges, selected/goal highlights, Clover bubble, and Clover target link.
- raw canvas-coordinate clicks select a build pad, a placed building, and Clover through `three-raycast`.
- the first browser-playable loop places a Lumber Camp, queues work, advances time, and collects outputs through existing game actions.
- Clover is represented in the Three.js scene without exposing worker/tool/provider jargon.

## Guardrails

- Do not fake world outcomes in the renderer.
- Do not move Foreman decision logic into backend shortcuts.
- Do not replace modal-first navigation with full-page navigation.
- Keep DOM or equivalent stable hooks for Playwright, keyboard focus, labels, and accessible object identity.
- If future work replaces sprite planes with GLB models, keep the same scene-state object IDs and `et.plot.*` mutation paths.
